# Loy Krathong Online

เว็บไซต์ลอยกระทงออนไลน์ พัฒนาด้วย PHP, HTML, CSS, JavaScript และ SQLite

## ความสามารถใน Phase 1

- หน้า Homepage เดิมพร้อมธีมสีเขียวเข้มและสีทอง
- ฟอร์มสร้างกระทงแบบ Guest ไม่ต้องสมัครสมาชิก
- ขั้นตอนสร้างกระทงแบบ Wizard: กรอกชื่อ → เลือกกระทง → เลือกชุดดอกไม้ → คำอธิษฐาน → ตรวจสอบ
- มีกระทงให้เลือก 10 แบบ และ **ชุดดอกไม้ 8 ชุด** (ชุดที่ 1–8 ชุดละ 5 ดอก เลือกครั้งเดียวไม่ต้องกดเพิ่มทีละดอก) ใช้ดอกไม้ครบทั้ง 15 ชนิด
- ภาพกระทงและดอกไม้ทั้งหมด **วาดเป็น SVG** (`includes/svg.php`) ไม่ใช้อิโมจิ
- **กรองคำหยาบ** (ไทย/อังกฤษ) ทั้งช่องชื่อเล่นและคำอธิษฐานที่เขียนเอง ตรวจทันทีระหว่างพิมพ์ และตรวจซ้ำฝั่งเซิร์ฟเวอร์ตอนบันทึก
- มีปุ่มย้อนกลับ/ถัดไป พร้อมแสดงความคืบหน้าและเก็บค่าที่เลือกไว้ระหว่างเปลี่ยนขั้นตอน
- เลือกคำอธิษฐานสำเร็จรูปหรือเขียนเอง
- แสดงตัวอย่างกระทงแบบ Real-time
- บันทึกกระทงและดอกไม้ลง SQLite ด้วย PDO transaction
- ตรวจสอบข้อมูลฝั่งเซิร์ฟเวอร์และ CSRF token
- สร้างตารางและเพิ่มข้อมูลกระทง/ดอกไม้เริ่มต้นอัตโนมัติเมื่อเปิดหน้า Create ครั้งแรก
- รองรับการอัปเกรดฐานข้อมูล Phase 1 เดิม โดยเพิ่มตาราง/คอลัมน์ที่จำเป็นอัตโนมัติ

## ระบบเสียง (เพลง / บรรยากาศ / เอฟเฟค)

- `assets/js/audio.js` คุมระบบเสียงทั้งหมด: **เพลงพื้นหลัง**เป็นไฟล์ `assets/audio/background-music.mp3` (เล่นวนซ้ำ ย่อเป็น 128 kbps ~3 MB) ส่วนบรรยากาศและเอฟเฟคสังเคราะห์ด้วย Web Audio API ไม่ใช้ไฟล์
- **เปลี่ยนเพลง** แค่แทนที่ไฟล์ `background-music.mp3` (ถ้าเพลงใหม่ดังหรือเบากว่าเดิม ปรับตัวคูณ `* 0.5` ใน `applyVolumes()`) เซิร์ฟเวอร์ต้องรองรับ HTTP Range (Apache/nginx รองรับอยู่แล้ว; `php -S` ไม่รองรับ จึงเล่นต่อตำแหน่งเดิมข้ามหน้าไม่ได้ตอนทดสอบในเครื่อง)
- **บรรยากาศ** สายน้ำ ลมกลางคืน จิ้งหรีด ระฆังวัดไกล ๆ พลุไกล ๆ
- **เอฟเฟค** แตะปุ่ม, เลือกกระทง/ดอกไม้/คำอธิษฐาน, เปลี่ยนขั้นตอน (ขั้นสูงขึ้นเสียงสูงขึ้น), เตือนคำไม่เหมาะสม, ปล่อยกระทงลงน้ำ, โคมลอย, เปิดอ่านคำอธิษฐาน, คัดลอกลิงก์
- เริ่มต้น **ปิดเสียง** (เบราว์เซอร์ไม่อนุญาตให้เล่นเองก่อนผู้ใช้แตะ) ผู้ใช้กดปุ่มลำโพงมุมจอเพื่อเปิด และปุ่มตั้งค่าเพื่อปรับระดับเสียง เพลง/บรรยากาศ/เอฟเฟค แยกกัน ค่าจะจำไว้ใน localStorage (`krathong-audio-v1`)
- จับเหตุการณ์ด้วย event / MutationObserver จึงไม่ต้องแก้สคริปต์เดิม หน้าไหนอยากมีเสียงให้ใส่ `<script src="…/audio.js">` ต่อจาก `script.js` (ต้องอยู่ก่อน `river.js`) เรียกเสียงเองได้ด้วย `KrathongAudio.play('splash')` ชื่อเสียง: tick select next back error chime ding whoosh lantern splash release success
- ปรับเสียงบรรยากาศที่ `buildAmbience()` / `startAmbienceLoops()`
- เพราะเป็นเว็บหลายหน้า เพลงจะเล่นต่อจากตำแหน่งเดิม (จำใน sessionStorage) เมื่อเปลี่ยนหน้า

## ความต้องการของระบบ

- PHP 8.2 ขึ้นไป
- เปิดใช้งาน `pdo_sqlite` และ `mbstring` ใน `php.ini`

## วิธีเปิดใช้งานบน Windows

1. เปิด `php.ini` ของ PHP ที่ใช้งาน
2. ตรวจสอบว่าเปิดใช้งาน extension ต่อไปนี้ (เอาเครื่องหมาย `;` ด้านหน้าออก หากมี)

   ```ini
   extension=pdo_sqlite
   extension=sqlite3
   extension=mbstring
   ```

3. เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วรัน:

   ```powershell
   php -m
   php -S localhost:8000
   ```

4. เปิด `http://localhost:8000`
5. เลือก “สร้างกระทง” เพื่อเริ่มทดสอบ ระบบจะสร้าง `database/database.sqlite` ให้อัตโนมัติ

- `admin/index.php` หน้าผู้ดูแล (แดชบอร์ด, กระทงทั้งหมด, รายงานกระทง, บันทึกกิจกรรม, ระบบ)

- `database/schema.sql` โครงสร้างตารางและข้อมูลกระทง 10 แบบ/ดอกไม้ 15 ชนิดตั้งต้น
- `includes/functions.php` ฟังก์ชันช่วยเหลือ, Escape HTML และโหลดชุดดอกไม้
- `includes/svg.php` ภาพ SVG ของกระทง 10 แบบ / ดอกไม้ 15 ชนิด (sprite ใช้ผ่าน `<use href="#kt-…">` / `<use href="#fl-…">`)
- `includes/profanity.php` ตัวกรองคำหยาบ
- `pages/check_text.php` API ตรวจคำหยาบให้หน้าเว็บเรียกแบบเรียลไทม์
- `database/seed.sql` ข้อมูลชุดดอกไม้และ svg_key (รันซ้ำได้ ทุกครั้งที่เชื่อมต่อฐานข้อมูล)
- `assets/css/style.css` รูปแบบเว็บไซต์
- `assets/js/create.js` Preview และการโต้ตอบของฟอร์ม

## การปรับแต่ง

- **เพิ่ม/แก้ชุดดอกไม้**: แก้ใน `database/seed.sql` (ตาราง `flower_sets` และ `flower_set_items`) แต่ละชุดต้องรวมกันได้ 5 ดอกพอดี ไม่เช่นนั้นจะไม่แสดง
- **เพิ่ม/ลบคำหยาบ**: แก้ที่ `profanityWordLists()` ใน `includes/profanity.php`
  - `loose` = ค้นหาทุกตำแหน่งในข้อความ (ตัดวรรณยุกต์ก่อนเทียบ)
  - `strict` = ค้นหาทุกตำแหน่งโดยคงวรรณยุกต์ (กันตัดสินผิด เช่น เหี่ยว/เหี้ย)
  - `token` = ต้องเป็นคำเดี่ยว ๆ เท่านั้น (กันตัดสินผิด เช่น ห่าง/ห่า, สัดส่วน/สัด)
  - `compact` = ตัดช่องว่าง/สัญลักษณ์ทั้งหมดก่อนค้นหา (จับ `f u-ck`, `b i t c h`) ใช้เฉพาะคำอังกฤษที่ไม่ซ้ำกับคำปกติ
  - `allow` = คำปกติที่มีคำหยาบอยู่ข้างใน (เช่น เหี้ยม, แม่งาน) ตัดทิ้งก่อนตรวจ กันตัดสินผิด
  - รอบนี้เพิ่มคำไทย/อังกฤษอีกมาก (คำด่า คำทางเพศ คำแช่ง คำเหยียด) และจับการหลบเลี่ยงเพิ่ม: พิมพ์วรรณยุกต์ก่อนสระ, ไม้ยมก (ๆ) แทรกกลางคำ, ตัวอักษรซีริลลิก/กรีกที่หน้าเหมือนละติน, ตัวเลขแทนตัวอักษร (8→b, 9→g) และแก้บั๊กเดิมที่ข้อความอย่าง `b8` ทำให้ตัวกรองล่ม
- **ฐานข้อมูลเก่า**: เปิดหน้าเว็บครั้งแรกระบบจะอัปเกรดให้อัตโนมัติ (รวมถึงตาราง `krathongs` รุ่นเก่าที่ใช้คอลัมน์ name/wish/design จะถูกแปลงโดยเก็บข้อมูลเดิมไว้)

## หมายเหตุ

ไฟล์ฐานข้อมูลจริง `database/database.sqlite` จะถูกสร้างในเครื่องและถูก ignore โดย Git ไม่ควร commit ไฟล์ฐานข้อมูลขึ้น Repository

## การนำขึ้นเซิร์ฟเวอร์ (ความปลอดภัย)

1. **ย้ายไฟล์ฐานข้อมูลไปไว้นอก web root** แล้วตั้ง environment variable เช่น
   `KRATHONG_DB_PATH=/var/lib/krathong/database.sqlite` (โฟลเดอร์ต้องเขียนได้โดยผู้ใช้ที่รัน PHP)
   ถ้าไม่ตั้ง จะใช้ `database/database.sqlite` ตามเดิม ซึ่งต้องกันไม่ให้ดาวน์โหลดได้
2. **Apache**: มี `.htaccess` กันโฟลเดอร์ `database/`, `config/`, `includes/` และไฟล์ `.sqlite` ให้แล้ว
   (ต้องเปิด `AllowOverride All`) — `php -S` ในเครื่อง **ไม่อ่าน** `.htaccess` ใช้เพื่อพัฒนาเท่านั้น
3. **nginx**: เพิ่มใน server block
   ```nginx
   location ~ ^/(database|config|includes)/ { deny all; }
   location ~* \.(sqlite|sqlite-wal|sqlite-shm|sql|md)$ { deny all; }
   ```
4. หลังตั้งค่าเสร็จ ลองเปิด `/database/database.sqlite` และ `/config/database.php` ในเบราว์เซอร์ ต้องได้ 403/404
5. ถ้าอยู่หลัง Cloudflare/Reverse proxy ตั้ง `KRATHONG_TRUST_PROXY=1` เพื่อให้ rate limit ใช้ IP จริง
   (อย่าเปิดถ้าไม่ได้อยู่หลัง proxy) และตั้ง `KRATHONG_BASE_URL=https://โดเมนของคุณ` เพื่อให้ og:url / og:image ถูกต้อง

## ผู้ดูแลระบบ (ซ่อนกระทงที่ไม่เหมาะสม)

1. สร้าง hash: `php -r "echo password_hash('รหัสผ่านของคุณ', PASSWORD_DEFAULT), PHP_EOL;"`
2. คัดลอก `config/admin.sample.php` เป็น `config/admin.php` แล้วใส่ hash (หรือตั้ง `KRATHONG_ADMIN_HASH`)
3. เปิด `/admin/` เพื่อเข้าสู่ระบบ กด "ซ่อน" เพื่อเอากระทงออกจากแม่น้ำ แกลเลอรี และหน้าแชร์ (ข้อมูลยังอยู่ในฐานข้อมูล กด "แสดงอีกครั้ง" ได้)

### รายงานกระทงที่ไม่เหมาะสม

- ผู้เข้าชมกด **⚑ รายงานว่าไม่เหมาะสม** ได้จากหน้าต่างคำอธิษฐานในหน้าแม่น้ำ/แกลเลอรี และจากหน้าแชร์กระทง (`pages/view.php`) เลือกเหตุผล (ภาษาหยาบคาย / เหยียดหยาม-กลั่นแกล้ง / เนื้อหาทางเพศ / ข้อมูลส่วนตัว / สแปม / อื่น ๆ) และพิมพ์รายละเอียดเพิ่มได้ไม่เกิน 200 ตัวอักษร (เลือก "อื่น ๆ" ต้องอธิบาย) แก้รายการเหตุผลที่ `REPORT_REASONS` ใน `includes/reports.php`
- รายงานถูกเก็บในตาราง `krathong_reports` (สร้างอัตโนมัติ — `DB_SCHEMA_VERSION` = 4) เก็บเฉพาะ hash ของ IP; **IP เดิมรายงานกระทงใบเดิมซ้ำไม่ได้** (unique `krathong_id + ip_hash`) และไม่เปิดเผยตัวผู้รายงานต่อเจ้าของกระทง
- ผู้ดูแลเห็นจำนวนที่รอตรวจที่เมนู **รายงานกระทง** (badge) และแบนเนอร์ในแดชบอร์ด แต่ละกระทงสรุปเหตุผล/จำนวนรายงาน และกดดูรายงานรายใบได้ การดำเนินการ:
  - **ซ่อนกระทง** → กระทงหายจากแม่น้ำ/แกลเลอรี/หน้าแชร์ และรายงานที่ค้างถูกทำเครื่องหมาย "ซ่อนกระทงแล้ว"
  - **ไม่พบปัญหา · ปัดตก** → รายงานถูกปัดตก กระทงแสดงตามเดิม
  - **ลบถาวร** → ลบกระทงและรายงานทั้งหมดของกระทงนั้น
  - ทุกการกระทำถูกบันทึกในหน้า "บันทึกกิจกรรม" ส่วนหน้า "กระทงทั้งหมด" มีตัวกรอง "มีรายงานรอตรวจ" และป้าย ⚑ ที่แถวกระทง
- ระบบจะ **ไม่ซ่อนกระทงอัตโนมัติ** ไม่ว่าจะมีรายงานกี่ครั้ง (กันการรุมรายงานกลั่นแกล้ง) ผู้ดูแลเป็นผู้ตัดสินเสมอ

## ผู้ดูแลระบบบนมือถือ (Responsive)

หน้าแอดมินรองรับมือถือ/แท็บเล็ต: จอ ≤ 900px เมนูข้างเป็น drawer (ปุ่ม ☰, ปิดด้วยการแตะพื้นหลังหรือกด Esc), ตารางกระทงและบันทึกกิจกรรมแสดงเป็นการ์ดทีละรายการ, แถบ "เลือกแล้ว N ใบ" ติดล่างจอให้กดด้วยนิ้วโป้งได้, ช่องกรอก 16px กัน iOS ซูมเอง และรองรับ safe-area ของ iPhone

## การป้องกันสแปม

- จำกัดการสร้างกระทงต่อ IP: 8 ครั้ง / 10 นาที และ 30 ครั้ง / วัน (แก้ได้ใน `pages/create.php`)
- การรายงานกระทงจำกัด 5 ครั้ง / 10 นาที และ 20 ครั้ง / วัน ต่อ IP (แก้ได้ใน `pages/report.php`) endpoint ตรวจ header `X-Requested-With` + `Origin` กันการส่งข้ามเว็บไซต์ และมี honeypot
- `check_text.php` จำกัด 90 ครั้ง / นาที, หน้า admin จำกัดการเดารหัสผ่าน 5 ครั้ง / 10 นาที
- มีช่อง honeypot ซ่อนไว้ในฟอร์ม สำหรับดักสคริปต์อัตโนมัติ
- ระบบเก็บเฉพาะ hash ของ IP ใน `rate_events` และลบของเก่าเกิน 1 วันเป็นระยะ

## ฐานข้อมูล: เวอร์ชัน schema

การสร้างตาราง/ย้ายข้อมูล/seed จะรัน **เฉพาะตอนที่ `PRAGMA user_version` ต่ำกว่า `DB_SCHEMA_VERSION`**
(`config/database.php`) ไม่ใช่ทุก request หากแก้ `schema.sql` หรือ `seed.sql` ให้เพิ่มเลข `DB_SCHEMA_VERSION` ด้วย
ไม่เช่นนั้นการแก้จะไม่ถูกนำไปใช้กับฐานข้อมูลเดิม ระบบเปิดโหมด WAL ด้วย จึงอาจเห็นไฟล์ `*.sqlite-wal` / `*.sqlite-shm` ข้างไฟล์ฐานข้อมูล (เป็นเรื่องปกติ)

## ประสิทธิภาพ (ข้อควรรู้เวลาแก้โค้ด)

- **กระทงในแม่น้ำเคลื่อนที่ด้วย `transform` เท่านั้น** (`assets/js/river.js` → `render()`): `left/top` ตั้งครั้งเดียวจาก PHP ห้ามแก้ซ้ำทุกเฟรม เพราะทำให้เบราว์เซอร์คำนวณเลย์เอาต์ใหม่ทั้งหน้า ขนาดกระทงเปลี่ยนเป็นขั้น (`SCALE_STEP`)
- **ไม่ใช้ `backdrop-filter`** ทับฉากที่ขยับตลอด (หิ่งห้อย/แม่น้ำ) เพราะต้องคำนวณเบลอใหม่ทุกเฟรม ใช้พื้นหลังทึบแทน
- **อนิเมชันที่ลื่น** ต้องเป็น `transform`/`opacity` เท่านั้น (ประกายน้ำ `.river-glint` และแถบน้ำ `.rw-band` เลื่อนด้วย transform บนเลเยอร์แยก) เปลวเทียนของกระทงคนอื่นอยู่นิ่ง เคลื่อนไหวเฉพาะกระทงของเราและตอนเอาเมาส์ชี้
- หิ่งห้อยลดเหลือ 12 ดวงบนมือถือ/เครื่องที่ CPU ≤ 4 คอร์ด
- `.htaccess` ตั้งแคชภาพ/เพลง 30 วัน, CSS/JS 1 วัน และบีบอัดข้อความ — เปลี่ยน CSS/JS แล้วผู้ใช้เก่าอาจเห็นของเดิมไม่เกิน 1 วัน
- `assets/images/backgrounds/river-lantern-night.png` คือต้นฉบับของพื้นหลังปัจจุบัน (โค้ดใช้ `.webp`); `river-night.*` / `river-moon.*` เป็นภาพเก่า ไม่ถูกเรียกใช้แล้ว ลบทิ้งได้

## เปลี่ยนภาพพื้นหลังแม่น้ำ / พื้นที่น้ำ

- ภาพที่ใช้ทั้งเว็บ: `assets/images/backgrounds/river-lantern-night.webp` (อ้างใน `style.css`, `index.php`, `pages/create.php`, `includes/functions.php`)
- **พื้นที่น้ำ** = `riverPolygon()` ใน `includes/functions.php` (พิกัดเป็น % ของภาพ) ใช้สามอย่างพร้อมกัน: (1) กระทงลอยอยู่ในพื้นที่นี้, (2) ตัดชั้นอนิเมชันน้ำด้วย `clip-path` (`riverClipPath()` → `.river-water` ใน `pages/river.php`), (3) ประกายหิ่งห้อยบนผิวน้ำ ถ้าเปลี่ยนภาพ ให้แก้พอลิกอนนี้ที่เดียว (และ `RIVER_Y_FAR` / `RIVER_Y_NEAR` = ขอบบน/ล่างของน้ำ)
- ตำแหน่งเอฟเฟกต์ที่ผูกกับภาพ (แสงโคม/วัด/พระจันทร์) อยู่ใน `$skyGlows`, `$shoreGlows` (`pages/river.php`), `.fx-moon` / `.fx-lamp-*` / `.river-glint .col` (`style.css`) และ `MOON`, `launchZones` (`river.js`)

## สถิติและอัปเดตสด

- **ยอดกระทง "ทั้งหมด / วันนี้"** แสดงที่หน้าแรก หน้าแม่น้ำ และหน้ารายการ (`krathongCounts()` + `renderKrathongStats()` ใน `includes/functions.php`) "วันนี้" นับตามเวลาไทย (Asia/Bangkok) แม้ฐานข้อมูลเก็บ UTC และไม่นับกระทงที่ผู้ดูแลซ่อน
- **อัปเดตสด** `pages/live.php` ส่ง JSON (ยอดกระทง + กระทงใหม่ที่ id > `after`) ให้หน้าแม่น้ำ (`river.js`) เรียกทุก ~22–30 วินาที (หยุดเมื่อแท็บถูกซ่อน และอัปเดตทันทีเมื่อกลับมา) กระทงใหม่จะลอยเข้าแม่น้ำเอง ส่วนหน้าแรก/หน้ารายการอัปเดตแค่ตัวเลข (`script.js`) endpoint นี้ไม่เริ่มเซสชันและอ่านอย่างเดียว
- **เพดานกระทงในแม่น้ำ**: 60 ใบ (เครื่องอ่อน/มือถือ/แรมน้อย = 24 ใบ) เกินแล้วกระทงเก่าสุดจะถูกเอาออกจากหน้าจอ (ไม่ได้ลบจากฐานข้อมูล) ปรับที่ `MAX_BOATS` ใน `river.js` และ `RIVER_MAX` ใน `pages/river.php`
- **บันทึกเป็นรูปภาพ** ที่หน้ากระทง (`view.php`) วาดเป็น PNG 1080×1350 ในเบราว์เซอร์ (`view.js`) ไม่ใช้เซิร์ฟเวอร์

## เช็กลิสต์ก่อนวันงานจริง

1. ตั้ง `KRATHONG_DB_PATH` ให้ไฟล์ฐานข้อมูลอยู่ **นอก web root** (เช่น `/var/lib/krathong/database.sqlite` โฟลเดอร์ต้องเขียนได้โดย user ของ web server)
2. อยู่หลัง Cloudflare/Reverse proxy ให้ตั้ง `KRATHONG_TRUST_PROXY=1` (ไม่เช่นนั้น rate limit จะมองทุกคนเป็น IP เดียวกันและบล็อกผู้ใช้ปกติ) และตั้ง `KRATHONG_BASE_URL=https://โดเมนของคุณ` เพื่อให้ลิงก์แชร์ (og:url) ถูกต้อง
3. ตรวจ `config/admin.php` ว่าเป็นรหัสผ่านของคุณเอง (ไม่ใช่ค่าตัวอย่าง) และไม่อยู่ใน git/ไม่ถูกส่งต่อ
4. เช็กว่าไม่มีคำเตือน PHP error ในล็อก
5. ลองแชร์ลิงก์หน้าแรกและ `view.php?id=…` ใน LINE/Facebook ดู preview, ทดสอบหน้าแม่น้ำบนมือถือรุ่นเก่า
6. วันงานให้มีคนเข้า `admin/` ตรวจรายงานเป็นระยะ

### ผลทดสอบการเขียนพร้อมกัน

จำลอง 20 โปรเซสเขียนพร้อมกันโปรเซสละ 25 ครั้ง (รวม 500 กระทงในธุรกรรมเดียวต่อครั้ง ผ่าน `getDatabase()` จริง): สำเร็จครบ ไม่มี "database is locked" ภายในราว 0.5 วินาที SQLite (โหมด WAL) รับกระทงใหม่ได้ระดับหลายร้อยใบต่อวินาที ซึ่งเกินความต้องการของเว็บนี้มาก

## แม่น้ำ: เมฆ โคมลอย และกระทงไม่ทับกัน

- **เมฆลอย**: สร้างด้วย JS (`river.js` → `riverClouds`, สไตล์ `.sky-cloud` ใน `style.css`) ลอยช้า ๆ **เฉพาะในพื้นที่ท้องฟ้าที่กำหนด** (`riverCloudPolygon()` ใน `includes/functions.php` เป็น % ของภาพ แก้จุดมุมได้ที่นั่นที่เดียว) มีหลายขนาด (เล็กอยู่สูง ใหญ่อยู่ใกล้แนวเขา), วางไม่ทับกันและไม่บังดวงจันทร์ (เช็กเส้นทางล่วงหน้าตอนเกิด) และค่อย ๆ จางเข้า-ออกทั้งตามอายุและเมื่อเข้าใกล้ขอบพื้นที่ เมฆที่วาดอยู่ในภาพคงเดิม
- **จำกระทงของผู้ใช้**: เบราว์เซอร์แต่ละเครื่องถือ token สุ่ม 256 บิตใน cookie `kt_owner` (HttpOnly, SameSite=Lax, 1 ปี ต่ออายุทุกครั้งที่เข้า) ฐานข้อมูลเก็บเฉพาะ SHA-256 ของ token ใน `krathongs.owner_token_hash` (ฐานข้อมูลอัปเกรดเองเมื่อเปิดเว็บ — `DB_SCHEMA_VERSION` = 5) หน้าแม่น้ำแสดงกระทงล่าสุดที่ผูกกับ token เป็น "กระทงของคุณ" ไม่เล่นอนิเมชั่นปล่อยซ้ำ ไม่มีระบบกู้คืน: ล้าง cookie หรือเปลี่ยนเครื่องจะไม่เห็นว่าอันไหนเป็นของตน หน้า river.php ส่ง `Cache-Control: private, no-store` **ถ้าอยู่หลัง CDN อย่าตั้งให้ cache HTML ของ `pages/river.php`** กระทงที่ลอยก่อนอัปเดตนี้ไม่มีเจ้าของ
- **โคมลอย** (`river.js` → `spawnOne`): ปล่อยทุก 2–5 วินาทีจากหลายจุดตลอดแนวฝั่ง พร้อมกันสูงสุด 8 ดวง (มือถือ 4)
- **กระทงของเรา**: ขนาดเท่ากระทงอื่น (`MINE_SCALE` = 1) แสดงชื่อและคำอธิษฐานตลอด คนอื่นเว้นที่ว่างรอบกระทงเรา (`MINE_HALO`)
- **กระทงไม่ทับกัน** (`river.js` → `avoid()` / `separate()`): แต่ละลำมีพื้นที่วงรี (`FOOT_X`, `FOOT_Y`) เลี้ยวหลบก่อนชน และถ้าซ้อนกันจะถูกดันออกในเฟรมนั้น กระทงที่อยู่ใกล้กว่าจะวาดทับลำที่ไกลกว่า (ตามความลึก)
- **ตำแหน่งเริ่มต้น** (`placeKrathongs()` ใน PHP): กระจายความลึกไกล–ใกล้ตามลำดับ golden ratio


## หมายเหตุด้านประสิทธิภาพ (Performance notes)

- `assets/js/river.js` ใช้ลูป `requestAnimationFrame` เดียวทั้งหน้า และหยุดเมื่อซ่อนแท็บ/เปิดหน้าต่างคำอธิษฐาน
- มีตัวคุมเฟรมเรตอัตโนมัติ: ถ้าเฉลี่ยต่ำกว่า ~38 fps ต่อเนื่อง จะเพิ่ม class `is-lite` แล้ว `is-min` ที่ `#riverView` เพื่อตัดเอฟเฟกต์ที่หนัก (ดูท้ายไฟล์ `style.css`)
- เอฟเฟกต์ที่หนักและถูกตัดออกถาวร: `mix-blend-mode: screen` และ `backdrop-filter` บนฉากที่ขยับตลอดเวลา
- CSS/JS ลิงก์ผ่าน `asset()` (ต่อ `?v=<เวลาแก้ไขไฟล์>`) จึง cache 30 วันได้ — ถ้าใช้ nginx ให้ตั้ง `expires 30d;` สำหรับ `/assets/`
- โฟลเดอร์ `_src/` เก็บไฟล์ต้นฉบับ/ภาพที่ไม่ได้ใช้ในเว็บ (PNG ต้นฉบับ, ภาพทดสอบ) — ไม่ต้องอัปโหลดขึ้นเซิร์ฟเวอร์ และถูกบล็อกใน `.htaccess`
